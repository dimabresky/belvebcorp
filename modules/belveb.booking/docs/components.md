# Декомпозиция макетов на компоненты

Документ описывает, как экраны модуля «Бронирование переговорных» из Figma раскладываются на Bitrix-компоненты, Vue-компоненты и серверные контроллеры модуля `belveb.booking`. Правила разработки — [`local/AGENTS.md`](../../../AGENTS.md). Структура данных — [`data-model.md`](data-model.md).

Файл Figma: `4Mn5pu8izGrpzESOU7NUxN` («Внутренний сайт Банка БелВЭБ»).

## Принципы

- PHP-компонент готовит `arResult` через сервисы модуля и выводит статичную часть страницы (заголовок, крошки). Интерактив — на Vue, встроенном в Bitrix Framework (`ui.vue3`), а не на отдельной сборке.
- Правила бронирования (пересечения, шаг сетки, права на отмену) живут в `lib/Domain/`. Ни шаблон, ни Vue-компонент их не дублируют: клиент показывает то, что ответил сервер, и отправляет намерения («забронировать 13:00–14:50»), а не результат. Те же объекты на JS дают мгновенный отклик до ответа сервера.
- Стили — утилиты Tailwind, собираемые CLI шаблона `belvebcorp` (`@source` уже указывает на `modules/belveb.booking` и `components`). Ручной CSS — только там, где утилит нет (например, выделение диапазона на таймлайне протяжкой).
- Один Vue-компонент — одна визуальная сущность. Если блок встречается на двух экранах, он общий; если один раз — живёт рядом с экраном.

## Bitrix-компоненты

Все компоненты лежат в `install/components/belveb/` и копируются в `local/components/belveb/` при установке модуля.

### `belveb:booking` — комплексный компонент

Разводит ЧПУ и подключает страничные компоненты:

```text
/booking/                → rooms  → belveb:booking.rooms
/booking/my/             → my     → belveb:booking.my
/booking/<ROOM_CODE>/    → room   → belveb:booking.room
```

Параметры: `SEF_MODE`, `SEF_FOLDER`, `SEF_URL_TEMPLATES`, `CACHE_TYPE`. Публичная страница `install/public/booking/index.php` вызывает только его. Сейчас страница вызывает `belveb:booking.rooms` напрямую — при переходе на динамику заменяется на комплексный компонент.

### `belveb:booking.rooms` — список переговорных

Переработка текущего статического компонента. `class.php` перестаёт хранить комнаты в коде и получает их из `RoomRepository` с учётом фильтра из `$_GET` (дата, время, участники, этаж, тип). В `arResult`:

- `FILTER` — нормализованный фильтр (значения по умолчанию: сегодня, ближайший час, 1 участник)
- `FILTER_OPTIONS` — список этажей и типов для выпадающих списков
- `ROOMS` — комнаты с признаком `IS_AVAILABLE` для выбранного диапазона
- `URLS` — ссылки на детальную и «Мои бронирования»

Шаблон выводит `h1`, крошки и монтирует `RoomsList` с `arResult` как начальным состоянием. Текущая разметка карточек из `template.php` переносится в `RoomCard` без изменения классов.

### `belveb:booking.my` — мои бронирования

`arResult`: `ACTIVE` (брони со статусом `booked`, где пользователь организатор или участник, от текущего момента), `PREVIOUS` (первая страница `completed` / `cancelled`), `NAV` (пагинация), `REPORT_URL`. Требует авторизации: неавторизованному показывается `system.auth.form` шаблона.

### `belveb:booking.room` — детальная переговорной

Параметр `ROOM_CODE` из ЧПУ. `arResult`: `ROOM`, `DAY` (выбранная дата, по умолчанию сегодня), `DAYS` (лента на 7 дней), `TIMELINE` (слоты дня с признаками «занято / ваша бронь», время обновления), `DAY_BOOKINGS` (таблица «Бронирования на дату»), `GRID` (рабочие часы и шаг сетки комнаты). 404, если комнаты нет или она не активна.

### Общий шаблонный код

Заголовок `h1` и хлебные крошки выводит шаблон сайта `belvebcorp`, не компоненты модуля. Комплексный компонент только вызывает `AddChainItem`. Страничные шаблоны монтируют Vue и не печатают заголовок. Языковые файлы — у каждого компонента свои, ключи с префиксом `BELVEB_BOOKING_*`.

## JS-расширение `belveb.booking`

Расширение регистрируется в `install/js/belveb.booking/` (копируется в `local/js/belveb.booking/`) и подключается `\Bitrix\Main\UI\Extension::load('belveb.booking')`. Зависимости в `config.php`: `ui.vue3`, `ui.vue3.vuex`, `main.core`, `ui.notification` (тосты), `main.date` (форматирование).

### Экранные компоненты (`src/screens/`)

- `RoomsList` — `BookingTabs` + `SearchBar` + `FilterChips` + заголовок «Доступные переговорные» + список `RoomCard variant="list"`. При изменении фильтра вызывает `Room.list`.
- `MyBookings` — `BookingTabs` + `SearchBar` + `FilterChips` + `ActiveBookingsList` (карточки `RoomCard variant="booked"`) + `PreviousBookings` (заголовок, кнопка «Скачать отчет», аккордеон `PreviousBookingRow` → `BookingDetails` с «Забронировать снова», `Pagination`). «Смотреть детали» открывает `BookingModal mode="edit"`, «Отменить встречу» — подтверждение и `Booking.cancel`, «Забронировать снова» — `BookingModal mode="rebook"`.
- `RoomDetail` — `RoomCard variant="detail"` + секция «Выберите время» (`DayPicker`, `Timeline mode="select"`, легенда, `TimeRangeControls`, подпись «Обновлено в HH:MM») + `DayBookingsTable` (Время, Тема, Организатор, «Отменить» для своих). Кнопка «Забронировать HH:MM – HH:MM» открывает `BookingModal mode="confirm"`.

### Хранилище

Одно Vuex-хранилище `booking` (`ui.vue3.vuex`) с модулями:

- `filter` — дата, диапазон времени, участники, этаж, тип
- `room` — текущая комната, выбранный день, таймлайн, выбранный диапазон
- `user` — ID и ФИО текущего пользователя, признак администратора модуля

Серверные ответы кладутся в хранилище как есть. Pinia, Vue Router и отдельная сборка Vue не используются.

### Взаимодействие с сервером

Все действия идут через `BX.ajax.runAction('belveb:booking.<Controller>.<action>')`. Ошибки контроллера (`Error` с кодом `TIME_BUSY`, `CAPACITY_EXCEEDED`, `ACCESS_DENIED`, `PAST_TIME`) отображаются `Toast kind="error"` или под полем формы. После успешного `add` / `update` / `cancel` клиент перезапрашивает таймлайн или список, а не правит состояние вручную.

## Контроллеры модуля (`lib/Controller/`)

Регистрируются в `.settings.php` модуля (`controllers.namespaces`), наследуют `\Bitrix\Main\Engine\Controller`, фильтры `Authentication` и `Csrf` по умолчанию.

| Контроллер | Действие | Назначение |
|------------|----------|------------|
| `Room` | `list` | Комнаты под фильтр с признаком доступности |
| | `get` | Комната по ID или коду |
| | `timeline` | Слоты занятости комнаты на день, время формирования |
| `Booking` | `add` | Создать бронь (и серию, если выбран повтор) |
| | `update` | Изменить тему, время, участников, описание |
| | `cancel` | Отменить одну бронь или всю серию |
| | `my` | Активные брони пользователя |
| | `previous` | Прошлые брони, страница `page` |
| | `nearestFree` | Ближайший свободный диапазон нужной длительности |
| | `report` | Выгрузка броней пользователя за период |
| `User` | `search` | Поиск сотрудников по ФИО для `ParticipantsPicker` |

## Доменные объекты (`lib/Domain/`)

Правила бронирования — неизменяемые объекты, не сервисные классы. Метод возвращает новый объект или ответ (`AcceptedDraft`, `RejectedDraft`, `NearestFree`, `NoFreeSlot`, `ClearRange`). Те же объекты и методы есть в JS-расширении `src/domain/`: интерфейс считает пересечение, длительность и вместимость сразу, сохранение повторяет проверку на PHP.

| Объект | Ответственность |
|--------|-----------------|
| `TimeRange`, `MinuteOfDay`, `Grid` | Интервал, шаг сетки, попадание в рабочие часы |
| `Timeline` | Слоты дня, пересечение, ближайший свободный интервал |
| `Room`, `RoomFilter` | Вместимость, этаж, тип, доступность комнаты на интервал |
| `ParticipantList` | Состав встречи и предел вместимости |
| `Booking` | Статус, право отмены, прошедшее время |
| `BookingDraft` | Намерение создать или изменить бронь, `confirm()` |
| `SeriesRule` | Повтор и список дат |

`FixtureCatalog` собирает фикстуры этими объектами, пока нет инфоблока. `ViewMapper` на клиенте поднимает объекты из снимка `view()`. Классов `AvailabilityService`, `BookingService`, `SeriesService` нет.

События Bitrix (`EventManager`) модуль публикует после операций: `OnBookingAdd`, `OnBookingUpdate`, `OnBookingCancel` — для интеграций сайта без правки модуля.

## Что происходит с текущим кодом

- `install/components/belveb/booking.rooms/class.php` — статические массивы `room()` и `amenities()` удаляются, данные приходят из `RoomRepository`.
- `templates/.default/template.php` — вёрстка карточки переносится в `RoomCard`, вёрстка фильтров в `SearchBar` и `FilterChips`; шаблон оставляет корневой `div` для монтирования Vue и JSON с начальным состоянием.
- `templates/.default/images/` — иконки оборудования перестают быть статикой компонента и становятся файлом `UF_ICON` справочника оборудования; остальные иконки переезжают в расширение `belveb.booking`.
- Фото четырёх залов — в `PREVIEW_PICTURE` элементов инфоблока.
